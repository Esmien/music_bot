# Документация:
Достаточно подробные докстринги ко всем функциям и классам строго в формате Google (Args, Returns, Raises).
Инлайн-комменты используем только для пояснения неочевидной бизнес-логики, спорных моментах и компромиссных решений.

# Обработка ошибок:
Ошибки логируются через встроенный модуль logging (уровень ERROR для сбоев сети, INFO для бизнес-событий). 
Запрещено использовать except Exception: pass без необходимости, отлавливаем конкретные исключения.
В крайнем случае используем contextlib.suppress.
Все необработанные исключения улетают в глобальный хэндлер on_error

# Именование:
Переменные и функции — snake_case, классы — PascalCase. 
Внутренние служебные функции начинаются с нижнего подчеркивания _
Названия переменных, методов, классов и объектов должны отражать их назначение, без абстрактных a, b, x и подобного

# Работа с функциями:
В сигнатуре функций и методов обязательны type hints.
Вызовы всех функций и методов строго с именованными аргументами, где это возможно

# Импорты:
Недопустимы относительные импорты. Все импорты делаются абсолютными

# Текст сообщений и логов
При отправке сообщений пользователю используется обращение на вы и русский язык
При отправке уведомления владельцу об ошибке, context преимущественно на русском языке
При записи в лог и написании сообщения исключения, например, Exception("message"), используется английский язык
