## TASK-004: Закрыть production infrastructure ports

- [ ] **Приоритет:** 🔴 P0 (BLOCKER)
	**Метки:** `security`, `reliability`
	**Проблема:** AUD-008. В production compose-файле наружу открыты порты `5432`, `6379`, `5672`, `15672`, при этом RabbitMQ имеет fallback-пароль `songai/songai`, а Redis не требует пароля.
	**Решение:**
	  1. Убрать секции `ports:` для баз данных, кэша и брокера из основного `docker-compose.yml`.
	  2. Вынести локальный доступ к портам в отдельный override (с привязкой только к `127.0.0.1`).
	  3. Сделать переменные учетных записей RabbitMQ обязательными, убрать небезопасные дефолты в коде конфигурации.
	  4. Обновить пример файла окружения `.env.example`.
	**DoD:**
	  - [ ] Production compose не открывает порты `5432`, `6379`, `5672`, `15672` на хост.
	  - [ ] Порты локальной разработки привязаны исключительно к `127.0.0.1`.
	  - [ ] При пустых credentials RabbitMQ приложение выдает ошибку валидации конфигурации на старте.
	  - [ ] Актуализирован `.env.example`.
