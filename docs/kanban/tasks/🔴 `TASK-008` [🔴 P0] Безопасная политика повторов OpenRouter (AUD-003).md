- [ ] **Приоритет:** 🔴 P0 (BLOCKER)
	**Метки:** `bug`, `money-loss`, `reliability`
	**Проблема:** AUD-003. Декоратор `@retry` оборачивает весь метод `generate_song_real`, включая чтение SSE-потока. При таймауте чтения после начала стриминга выполняется повторный POST-запрос, приводящий к двойной оплате.
	**Решение:**
	  1. Разделить pre-request сбои (ошибки подключения до отправки запроса) и post-request сбои (таймауты в процессе стриминга).
	  2. Запретить автоматический retry после успешного установления стрима или отправки данных.
	  3. Добавить классификацию статусов ошибок (не повторять клиентские 4xx, кроме явных 429).
	**DoD:**
	  - [ ] Разрыв или таймаут во время чтения SSE-потока не инициирует повторный POST-запрос.
	  - [ ] Ошибки `400` и прочие non-retryable статусы не повторяются.
	  - [ ] В логах предупреждений фиксируются `gen_id`, `attempt_id` и фаза сбоя.
	  - [ ] Правила зафиксированы в `CONVENTIONS.md`.
	  - [ ] Ruff, Mypy, Pytest проходят без ошибок.
