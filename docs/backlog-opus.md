### TASK-007: Атомарный claim платной генерации
- **Приоритет:** P0 (BLOCKER)
- **Метки:** `bug`, `money-loss`, `reliability`
- **Проблема:** AUD-002. Воркер читает статус `PENDING`, закрывает транзакцию, а затем отправляет платный HTTP-запрос к API. При повторной доставке сообщения возможен параллельный запуск двух платных запросов для одного `gen_id`.
- **Решение:**
  1. Ввести промежуточный статус (например, `PROCESSING`) и уникальный идентификатор попытки (`attempt_id`).

  3. Если ни одна строка не обновилась — воркер завершает задачу без вызова внешнего API.
- **DoD:**
  - [ ] Создана миграция БД для статуса и атрибутов попытки.
  - [ ] Написан интеграционный тест на конкурентный claim (два воркера -> ровно один внешний API call).
  - [ ] Повторная доставка обработанного события не приводит к списанию и вызову API.

### TASK-008: Безопасная политика повторов OpenRouter

- **DoD:**
  - [ ] Разрыв или таймаут во время чтения SSE-потока не инициирует повторный POST-запрос.
  - [ ] Ошибки `400` и прочие non-retryable статусы не повторяются.
  - [ ] В логах предупреждений фиксируются `gen_id`, `attempt_id` и фаза сбоя.
